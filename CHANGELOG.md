# Изменения

## Как устроены версии

`versionName` = `1.0.<номер прогона CI>`, `versionCode` = `1000 + <номер прогона>`.
Номер прогона берётся из `GITHUB_RUN_NUMBER`, то есть **каждая сборка с Actions
новее предыдущей** — Android больше не откажется поставить её поверх.

Локальная сборка получает `1.0.0-local` и `versionCode = 1`, поэтому сборка с CI
всегда её перекрывает, а не наоборот.

Версия и короткий хеш коммита видны на стартовом экране: `LiPlayer 1.0.42 · 38de6bd`.
Это единственный надёжный способ понять, что именно стоит на телевизоре.

### Имя файла сборки

```
LiPlayer-v1.0.<номер прогона>-<ДДММГГГГ>[-<ветка>].apk
```

Например `LiPlayer-v1.0.42-22082026.apk` для сборки из `main` и
`LiPlayer-v1.0.43-22082026-dev.apk` для ручной сборки с `dev`.

Номер прогона в имени оставлен намеренно: двух сборок в один день дата не
различает, а суффикс ветки не даёт спутать проверенное в `main` с черновым `dev`.

### Когда собирается

| Событие | Сборка |
|---|---|
| Мерж PR в `main` (то есть push в `main`) | автоматически |
| Push в `dev` | нет |
| Actions → Build APK → Run workflow | вручную с любой ветки |

## Известные регрессии и их причины

### Два вида чёрных полос

Это не баг, а два разных случая, которые долго путались.

**Аппаратные полосы** — соотношение кадра не совпадает с экраном, полосы
добавляет плеер. Их толщина известна, поэтому авто-сдвиг «вверх/вниз до края»
работает.

**Полосы, впечатанные в кадр** — 2.35:1 закодировали внутрь 16:9. Для плеера это
обычное 16:9 видео, полос для него не существует, авто-сдвиг вернёт ноль. Такие
полосы убираются только ручным сдвигом, который двигает кадр целиком и выносит
часть его за пределы экрана.

### Регрессия сдвига

**Сдвиг перестал работать после `cd60193`** — подтверждено разбором.
До этого коммита `applyScreenSize()` только выставляла масштаб. В `cd60193` в неё
добавился пересчёт геометрии, а пересчёт заново вычисляет сдвиг из режима: для
16:9 контента предел равен нулю, поэтому любое применение размера экрана
сбрасывало сдвиг в 0. Вторая причина — `translationY` не двигает видео на
`SurfaceView`. Обе устранены в `38de6bd`.

**Ничего из перечисленного не собиралось.** Все коммиты написаны без компилятора:
Android SDK на машине разработки отсутствует, а сборка на CI до сих пор ни разу не
запускалась. Первая сборка почти наверняка покажет ошибки — самые вероятные места
это вызовы API Media3, у которых мог отличаться набор параметров.

Быстрее всего проверить это ручным запуском с `dev`:
Actions → Build APK → Run workflow → ветка `dev`.
